# 02. 開発ガイド（コードの直し方・公開のしかた）

プログラミングに詳しくない方でも、**よくある修正**なら自分でできるように書いています。

---

## 1. 仕組みのあらまし

このアプリは **HTMLファイル1つだけ** で動きます。

```
outline.html  ←  これ1つがアプリの全部（画面・処理・デザイン）
```

- インストールや「ビルド」といった作業は**一切不要**です
- ファイルを直して GitHub に保存すれば、**数分で自動的にWebサイトに反映**されます
- データ（マスター・計画・実績）だけは Firebase というクラウドに保存されます

### 使っている技術

| 技術 | 役割 | 読み込み方 |
|---|---|---|
| React 18 | 画面を組み立てる | インターネットから自動読込 |
| Babel | 書き方を変換する | 同上 |
| Firebase 8.10.1 | データの保存・ログイン | 同上 |
| QRious | QRコードを表示する | 同上 |

> ⚠️ **インターネット接続が必須**です。社内LANのみ／オフラインでは動きません。

---

## 2. 修正して公開する手順（いちばん簡単な方法）

**GitHubのサイト上で直接編集できます。** パソコンに何も入れる必要はありません。

1. GitHub でこのリポジトリを開く
2. `outline.html` をクリック
3. 右上の **鉛筆マーク（✏️ Edit）** をクリック
4. 直したい場所を探して書き換える（`Ctrl + F` で検索できます）
5. 下の **Commit changes** をクリック
   - 「何を直したか」を一行書いておくと後で分かりやすいです
   - 例：`注意ポイントの文字を大きくした`
6. **2〜3分待つ** → 自動でWebサイトに反映されます

### 反映されたか確認する

- リポジトリの **Actions** タブを開く
- 緑のチェック ✅ が付いていれば公開完了
- 赤い × が出たら、どこか書き間違えています（下の「困ったとき」参照）

## 4. よくある修正のやり方

### ■ 工程の名前を変える・増やす

`Ctrl + F` で `const PROCESSES=[` を検索。

```js
const PROCESSES=[
  {id:'p1', no:1,  ja:'製品揃え',  id_:'Penyiapan Produk', icon:'📋'},
  //                  ↑日本語名      ↑インドネシア語名      ↑アイコン
```

- **名前を変える** → `ja:'...'` の中身を書き換え
- **工程を増やす** → 行をコピーして `id` を**他と重複しない値**に（例 `p11`）、`no` を連番に

> ⚠️ `id`（`p1` など）は**絶対に変えないでください。**
> 登録済みのマスターや計画データがこの `id` で紐付いているため、変えると繋がりが切れます。

### ■ 画面の文字を変える

**日本語だけ変えたい場合** → その文字を `Ctrl + F` で検索して書き換え

**インドネシア語も直したい場合** → `const DICT={` を検索。対訳表になっています。

```js
'計画表':'Jadwal Kerja',
//  ↑日本語   ↑インドネシア語
```

### ■ 文字の大きさ・色を変える

`fontSize:14` のような部分を探して数字を変えます（単位はピクセル）。
色は `color:'#111'` のような部分です。

主な色は先頭でまとめて定義されています。

```js
const NAVY='#12306B';   // 濃紺（ヘッダー・ボタン）
const BLUE='#1B4A9C';   // 見出しの青
```

### ■ QRコードリーダーを導入したとき

`Ctrl + F` で `QR_ENABLED` を検索し、`false` を `true` に変えるだけです。

```js
const QR_ENABLED=false;   →   const QR_ENABLED=true;
```

これで「担当者QR」「ガイドQR読取」「製品QR照合」「かんばんQR照合」が一斉に使えるようになります。

### ■ 始業時刻・休憩時間を変える

コードを触る必要はありません。
アプリの **スケジュール編集 →「⏰ 始業・休憩設定」** で工程ごとに設定できます。

## 5. 直す前に必ずやること

### ① バックアップを取る

GitHub は履歴が残るので元に戻せますが、念のため編集前のファイルを手元に保存しておくと安心です。

### ② いきなり本番を直さない

**生産計画（`nagasaka.html`）は本番稼働中です。** 現場が使っている最中に壊すと作業が止まります。

おすすめの手順：
1. まず `outline.html`（テスト中）で練習する
2. 現場が使っていない時間帯（昼休み・終業後）に変更する
3. 変更後すぐに実機で動作を確認する

### ③ 元に戻したくなったら

1. リポジトリの **Commits**（履歴）を開く
2. 戻したい時点の変更を開く
3. **Revert** ボタンで取り消せます

## 6. 困ったとき

| 症状 | 原因・対処 |
|---|---|
| 画面が真っ白になった | 書き間違いです。Commits から Revert して戻してください |
| Actions が赤い × | 同上 |
| 「接続に失敗しました」と出る | Firebase の権限ルールの問題です。杉本に連絡してください |
| データが保存できない | 同上 |
| 翻訳されない | 翻訳サービス側の問題です。日本語のままでも使えます。杉本に連絡 |
| 画像がアップロードできない | ファイルサイズが4MBを超えていないか確認してください |
| ログインできない | アカウントの問題です。杉本に連絡してください |

### 画面が真っ白になったときの応急処置

1. GitHub の **Commits** タブを開く
2. 一番上（最新）の変更をクリック
3. 右上の **…** → **Revert** → **Commit changes**
4. 2〜3分で元に戻ります
