## 更新の基本手順

- Pagesで配信するHTMLに翻訳Workerを同梱し、ビルドのGit SHAを埋め込む。旧版のWorkerファイルも配信する。HTMLと別ファイルのWorkerが異なる版になる問題を防ぐため、旧版用ファイルの互換性を維持する。
- アプリ内の自動確認と手動更新は、工程選択または操作中のダイアログがない計画表で行う。台帳上で作業中の指示をこのタブで開いた場合は、別画面に移ってもその指示が完了するまで更新を保留する。通信、Firestoreの書き込み確認、検査中に操作や画面遷移が発生したかも確認する。
- ブラウザーやOSの強制終了でアプリが終了する場合、未保存入力の保持は保証できない。現場ではブラウザーの再読み込みボタンより、作業終了と保存確認後のアプリ内更新を使う。
- 初回切り替え時は旧版の更新処理が休憩・応援中にも動き得る。旧版が残る端末の作業をすべて終了し、保存済みと確認した時間帯に初回を公開する。

## 検証環境と公開判断

- 隔離したFirestore Emulatorに実際に書き込み、別ブラウザー画面からサーバー読み直しを実施。競合する休憩推定の記録が1件になり、根拠不足が未判定で保存されたことを確認。通信停止中に保留した書き込みが、復旧・確認後の画面更新をまたいで残ることを確認。
- 休憩確認と評価の休憩一覧が数値の日時を表示した際に画面が止まる問題を修正。日時の表示関数で数値とDateの両方を扱う。
- 切り替え終了を記録した文書を読み直し、切り替えロスの計算で保存済みの終了時刻を上限にすることを確認。14分の間隔で9分、重複する除外時間を1回だけ差し引くケースも確認。
- 公開前に、切り替え終了ボタンからの保存、本人回答と推定の競合、7日超、日・週・月・年・時間帯の評価、その他ロス、確定済み評価の保持、新旧同時使用、初回公開時の端末安全性、全工程と4言語を引き続き検証する。検証と修正は現場の生産データから隔離する。
- 実機では検証用指示を開き、縦横それぞれでカメラと外付けQRリーダーを試す。一致で1箱だけ増え、再読は二度読み防止、異品番では停止、管理者解除後に照合を再開することを確認。作業中に更新を試し、終了・保存後に計画表を開いてバージョン、担当者、対象日、次品番、箱数を確認する。
- 復旧は初回公開前のデプロイを特定し、候補を反映した変更の取り消しをレビューしてPagesで再配信する。HTMLのハッシュと版表示を照合し、端末は作業終了後に順次更新する。アプリの再配信でFirestoreの記録は巻き戻らないため、データ復旧が必要な場合は対象を特定して別途扱う。
